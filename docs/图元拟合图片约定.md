# 图元拟合图片约定

千星奇域不能导入外部图片。Diapig Editor 的「更多 → 图元拟合」把一张图片拟合成几百个染色、半透明的基础图元（矩形、圆、三角形及软边渐变），导出为一个 Lua 数据模块；游戏里的 Lua 把它画成一组图片控件。本文约定数据格式、Lua 引用方法和绘制方法。

- 建立日期：2026-11-14；2026-11-15 增补软图元格式、逐类型图片模式与标定依据，并约定保留透明背景的 format 3、Alpha 误差与参考读取器兼容规则。
- Lua 导出只写用户在保存对话框里选定的 `.lua`。像素画也可单独导出 PNG。
- 关闭「保留透明度」时沿用不透明背景：纯硬图元使用 In Falsus 曲封兼容的 `format = 1`；导出记录中含任一软图元（kind 4–6）时使用 `format = 2`。开启后生成透明画布（`bg = 0`、`bgAlpha = 0`），使用 `format = 3`，即使只有硬图元或没有图元也不降版。旧版读取器必须按所支持的版本拒绝新格式，不能忽略透明度按旧格式画底。
- 编辑器「拟合与导出」里的「复制 Agent 提示词」按钮内置了本约定的自含版本（不依赖本机文档、Skill 与模板 ID，供其他设备上的 Agent 使用），第 4 节的参考代码以 `src/model/PrimArtView.lua` 原样嵌入。修改第 4 节代码时同步更新该文件，`agentPrompt.test.ts` 会检查两者逐字一致（2026-11-15）。
- 标定详见 [渐变图元标定](渐变图元标定.md)。新实现的桌面检查属于 `inferred`，新图元引擎实机验证为 `pending`；核心与前端的最终检查结果由主任务汇总。

## 1. 数据模块

图元拟合导出的文件是一个纯数据模块，只有注释和一个 `return` 表：

```lua
-- PrimArt.lua：图元拟合图片（由 Diapig Editor 图元拟合生成，请勿手动修改格式）
-- 源图 cover.png，200×200，500 个图元，相似度 93.3%
return {
format=1,w=200,h=200,bg=0x2A2B33,
shapes={
2,109,61,57,99,82,0xE5A39DE7,
1,152,113,35,203,9,0x18F8F0FF,
},
}
```

| 字段 | 含义 |
| --- | --- |
| `format` | `1`：不透明背景，仅 kind 1–3；`2`：不透明背景，支持 kind 1–6；`3`：显式背景 Alpha，支持 kind 1–6。旧不透明路径截取前缀后按实际 kind 选择 1/2；透明拟合及其前缀使用 3 |
| `w`、`h` | 画面的宽和高，以图元坐标为单位。图元拟合按工作分辨率输出，像素画按实际宽高的两倍输出。显示时可按任意宽度等比缩放 |
| `bg` | 背景色 `0xRRGGBB`，也是外层遮罩矩形的 RGB；透明拟合实际生成 `0` |
| `bgAlpha` | 背景不透明度，u8 整数（0–255）。format 1/2 可省略，缺省为 255；即使提供也须校验范围，但按旧格式绘制时仍用 255。format 3 必填，读取器接受 0–255；透明拟合实际生成 0 |
| `shapes` | 每 7 个整数一个图元，按叠放顺序从下到上排列 |

每个图元的 7 个整数：

| 序号 | 含义 |
| --- | --- |
| 1 | 类型 kind：见下表。format 1 只允许 1–3，format 2/3 允许 1–6；未知 kind 必须拒绝，不得退回矩形 |
| 2、3 | 中心 x、y。原点在画面左下角，X 向右、Y 向上 |
| 4、5 | 宽、高，即控件的 `sizeDelta`。椭圆是两条轴的直径，三角形是底边宽和高 |
| 6 | 旋转角（整数度），逆时针为正，即 `SetLocalRotation(0, 0, r)`。kind 1/2/4/6 为 0–179；有方向的 kind 3/5 为 0–359 |
| 7 | 颜色 `0xAARRGGBB`，AA 是不透明度（1–255） |

三种格式共用 `format,w,h,bg,shapes` 与相同的 **7 整数步长**；format 3 另有必填的 `bgAlpha`。软图元没有额外参数，衰减函数由 kind 唯一确定。每条颜色仍为非预乘的 `0xAARRGGBB`，每层的纹理 Alpha 再乘 AA；预乘只用于拟合计算，不要把预乘 RGB 写入颜色字段。

`format=3,w=200,h=200,bg=0,bgAlpha=0,shapes={}` 是有效的全透明数据，可以导出和读取；绘制时只创建一个透明外层遮罩，没有图元子控件。

「更多 → 像素画生成」使用同一 `format = 3`，以透明裁切层承载不重叠的硬矩形，每个成品像素占 2×2 个 Lua 坐标单位。例如，3×2 px 的 PNG 对应 `w=6,h=4`，从左上角起第一个单位像素用中心 `(1,3)`、宽高 `(2,2)` 表示。较小的模块直接返回字面量表，调色板、尺寸字典和坐标差分能节省体积时，模块在 `require` 中自行还原同一张表。图元拟合的前缀用法适用于渐进拟合结果，像素画绘制时传入完整数据。控件计数同样包含 1 个外层遮罩。

| kind | 名称 | 素材 ID | `Enum.ImageType` | 局部形态（旋转前） |
| --- | --- | --- | --- | --- |
| 1 | 硬矩形 | 100001 | `Stretch` | 全矩形 |
| 2 | 硬椭圆 | 100002 | `Stretch` | 内切椭圆 |
| 3 | 硬等腰三角形 | 100003 | `Stretch` | 尖顶朝局部 +Y |
| 4 | radial / 径向软椭圆 | 106057 | **`Basic`** | 中心满、向内切椭圆边界衰减，四角透明 |
| 5 | linear / 单向渐变矩形 | 106093 | **`Stretch`** | 局部左满 → 右空；纵向常值（保护边除外） |
| 6 | band / 对称高光带 | 106091 | **`Stretch`** | 局部左空 → 中央满 → 右空；纵向常值（保护边除外） |

kind 4 固定使用 106057，不随尺寸换素材。径向使用 Stretch 会触发九宫格平顶；线性使用 Basic 会放大图集保护边，二者都改变拟合依据。软边来自图片 Alpha，不开启 `enableSoftEdge`。

说明：

- 坐标和旋转方向与引擎一致（`docs/UI布局与图片语义.md`：布局 Y 向上，旋转逆时针为正），绘制时不用取负或翻转。
- 图元可以超出画面范围，由外层遮罩裁掉。
- 图元必须按顺序叠放：半透明颜色是按「后画的盖在先画的上面」算出来的，顺序变了颜色就不对。
- 体积：每个图元一行，约 30 字节。300 / 500 / 1000 个图元约 9 / 15 / 29 KB。

## 2. 控件数量与前缀

- 控件数 = 图元数 + 1（外层遮罩）。
- 拟合是贪心的：每次加一个让误差下降最多的图元。所以**前 k 个图元本身就是「只用 k 个图元」时的结果**。
  - 工具里的「使用前 k 个」滑条就是在截取前缀，导出的文件只含这 k 个。
  - 游戏里也可以只画前缀：同一份数据，大图画全部，缩略图只画前 100 个，不用导出两份。
  - 开了「精修」时，图元是按「全部一起显示」再调整过的，前缀不再严格是 k 个图元时的最好结果。精修还会把少数贡献最小的图元搬到最上层的新位置，叠放顺序因此有小幅变化。实测影响很小（1000 个图元精修 2 轮后，只取前 500 个的相似度从 93.63% 降到 93.45%），前缀照常可用。要让缩略图本身最好，就单独导出一份图元数少的。
- 图元越多越像，但创建越慢。按第 4 节的分帧方式创建，并用最大规模实机确认帧率（AGENTS 第六章）。

## 3. 在 Lua 里引用

1. 把导出的 `.lua` 放进项目的 `external_lua_file`（可以放在子文件夹里）。
2. 在千星沙箱「客户端脚本资源管理器」里为它建立同名脚本映射（文件名去掉 `.lua`，保留大小写；步骤见 `docs/编辑器操作指引.md` 2.1）。只建映射，不挂载。没有映射的文件 `require` 不到，也不进存档。
3. 在 `编辑器数据表.md` 的脚本映射表里登记一行。
4. 按「按需数据模块」的方式取用（AGENTS 4.1）：
   - 用 `pcall(require, name)` 取表。根目录写 `require("PrimArt")`，子文件夹写 `require("子文件夹.PrimArt")`。
   - 核对 `format` 为 1、2 或 3、`#shapes % 7 == 0`、记录字段为整数且尺寸/颜色有效，并按版本检查 kind。format 1 中的软 kind 与任何未知 kind 都拒绝；format 3 缺少 `bgAlpha`、或任一格式提供了非 u8 的 `bgAlpha`，也须拒绝。参考读取器允许 format 2 的硬图元前缀，以及 format 3 的硬图元前缀和空 `shapes={}`；透明拟合的前缀不降为 1/2。模块缺失或格式不对时降级（比如显示占位提示），并打一条日志。
   - 取到后执行 `package.loaded[name] = nil`。控件建完、不再持有这张表后，原始数据就能被回收。
5. 导出时工具要求模块名只含字母、数字、下划线，且文件名等于模块名。保存时改了文件名的话，映射名和 `require` 的名字都跟着文件名走。

`require` 有缓存：重新导出同名文件后，要重新进入试玩才会读到新数据。

## 4. 参考绘制代码

下面的模块只用官方 API，不依赖任何项目的上下文。可以原样放进项目（建映射 `PrimArtView`），也可以把其中的做法并进项目自己的控件工厂。

```lua
-- PrimArtView：图元拟合图片（Diapig Editor「图元拟合」导出的数据模块）的通用绘制。
-- 只用官方 API，不依赖任何项目的上下文；imagePrefab 是图片控件（ClientUIImageControl）的模板索引。
-- 模块返回安装函数，导入阶段不创建控件。
return function(imagePrefab)
    local V = {}
    -- kind → {素材 ID, 图片模式}；软边在纹理中，不能给所有素材统一设 Stretch。
    local ASSETS = {
        { 100001, Enum.ImageType.Stretch },
        { 100002, Enum.ImageType.Stretch },
        { 100003, Enum.ImageType.Stretch },
        { 106057, Enum.ImageType.Basic },
        { 106093, Enum.ImageType.Stretch },
        { 106091, Enum.ImageType.Stretch },
    }

    local function integer(value)
        return type(value) == "number" and value % 1 == 0
    end

    local function validate(art)
        if type(art) ~= "table" or (art.format ~= 1 and art.format ~= 2 and art.format ~= 3) then return nil, "bad_format" end
        if not integer(art.w) or not integer(art.h) or art.w <= 0 or art.h <= 0 then return nil, "bad_size" end
        if not integer(art.bg) or art.bg < 0 or art.bg > 0xFFFFFF then return nil, "bad_bg" end
        if art.format == 3 or art.bgAlpha ~= nil then
            if not integer(art.bgAlpha) or art.bgAlpha < 0 or art.bgAlpha > 255 then return nil, "bad_bg_alpha" end
        end
        if type(art.shapes) ~= "table" then return nil, "bad_shapes" end
        local shapes, n = art.shapes, #art.shapes
        if n % 7 ~= 0 then return nil, "bad_stride" end
        -- 不接受稀疏数组、额外键或非整数，避免 # 的边界掩盖损坏记录。
        for key, value in pairs(shapes) do
            if not integer(key) or key < 1 or key > n or not integer(value) then return nil, "bad_shapes" end
        end
        for i = 1, n, 7 do
            for j = i, i + 6 do
                if not integer(shapes[j]) then return nil, "bad_record:" .. i end
            end
            local kind, color = shapes[i], shapes[i + 6]
            if not ASSETS[kind] or (art.format == 1 and kind > 3) then return nil, "bad_kind:" .. i end
            if shapes[i + 3] <= 0 or shapes[i + 4] <= 0 then return nil, "bad_shape_size:" .. i end
            local turn = (kind == 3 or kind == 5) and 360 or 180
            if shapes[i + 5] < 0 or shapes[i + 5] >= turn then return nil, "bad_rotation:" .. i end
            if color < 0x01000000 or color > 0xFFFFFFFF then return nil, "bad_color:" .. i end
        end
        return art
    end

    local function rgb(value, alpha)
        return Color((value >> 16) & 255, (value >> 8) & 255, value & 255, alpha)
    end

    local function newImage(parent, name, asset, color)
        local image = game.InstantiateClientUIControl(imagePrefab, parent)
        if not image then error("primart_create_failed:" .. name) end
        image:SetVisible(false)
        image.name = name
        image:SetActive(true)
        local assetId = asset[1]
        image:SetImage(Enum.ImageSource.StaticReference, assetId)
        if image.imageSource ~= Enum.ImageSource.StaticReference or image.imageId ~= assetId then
            error("primart_bind_failed:" .. name)
        end
        image.imageType = asset[2]
        image.imageColor = color
        image.enableMask = false
        image.enableSoftEdge = false
        image.reverseMaskArea = false
        image:SetFillUnused()
        image:SetPivot(0.5, 0.5)
        return image
    end

    --- 取出数据模块。moduleName 是 require 用的名字（放在子文件夹里时写 "子文件夹.模块名"）。
    --- 成功返回 art；模块缺失（没有脚本映射）或格式不对时返回 nil 和原因。
    function V.load(moduleName)
        local ok, art = pcall(require, moduleName)
        -- 不留在 require 缓存里：控件建完、调用方丢掉 art 后，原始表即可回收
        package.loaded[moduleName] = nil
        if not ok then return nil, "require_failed:" .. tostring(art) end
        return validate(art)
    end

    --- 分步绘制。先建好遮罩，之后每次 builder.step(budget) 最多再建 budget 个图元，全部建完返回 true。
    --- parent：父控件；x, y：遮罩中心相对父控件中心的偏移（父级局部坐标，Y 向上）；width：显示宽度，高度按比例；
    --- count：只画前 count 个图元（缺省为全部）。
    function V.begin(parent, name, art, x, y, width, count)
        local valid, why = validate(art)
        if not valid then error("primart_invalid:" .. why) end
        local k, shapes = width / art.w, art.shapes
        local total = math.min(count or math.huge, #shapes // 7)
        local maskAlpha = art.format == 3 and art.bgAlpha or 255
        local mask = newImage(parent, name, ASSETS[1], rgb(art.bg, maskAlpha))
        mask:SetAnchorMin(0.5, 0.5)
        mask:SetAnchorMax(0.5, 0.5)
        mask:SetSizeDelta(width, art.h * k)
        mask:SetAnchoredPosition(x, y)
        -- 正遮罩：只保留遮罩矩形内的子内容；自身 Alpha 为 0 时仍可裁切子图片
        mask.enableMask = true
        mask.reverseMaskArea = false
        mask:SetVisible(true)

        local builder = { mask = mask, parts = {}, total = total, done = total == 0 }

        function builder.step(budget)
            local parts = builder.parts
            local last = math.min(total, #parts + (budget or math.huge))
            for index = #parts + 1, last do
                local i = (index - 1) * 7 + 1
                local value = shapes[i + 6]
                local part = newImage(mask, name .. "_" .. index, ASSETS[shapes[i]], rgb(value, (value >> 24) & 255))
                -- 表中坐标以遮罩左下角为原点、Y 向上：锚点放在父级左下角，anchoredPosition 就是图元中心
                part:SetAnchorMin(0, 0)
                part:SetAnchorMax(0, 0)
                part:SetSizeDelta(shapes[i + 3] * k, shapes[i + 4] * k)
                part:SetAnchoredPosition(shapes[i + 1] * k, shapes[i + 2] * k)
                part:SetLocalRotation(0, 0, shapes[i + 5])
                part:SetVisible(true)
                parts[index] = part
            end
            builder.done = #parts >= total
            -- 建完后不再引用原始数据，让它可以被回收
            if builder.done then shapes = nil end
            return builder.done
        end

        --- 销毁全部控件（图元随遮罩一起销毁）；可重复调用。
        function builder.destroy()
            if builder.mask then game.DestroyClientUIControl(builder.mask) end
            builder.mask, builder.parts, builder.done, total, shapes = nil, {}, true, 0, nil
        end

        return builder
    end

    return V
end
```

入口里的用法（示意）：

```lua
-- OnInit / 装配阶段
local PrimArtView = require("PrimArtView")(IMAGE_PREFAB)   -- 图片控件模板索引，见 编辑器数据表.md

-- 页面打开时
local art, why = PrimArtView.load("PrimArt")
if not art then
    printerr("[PrimArt] 读取失败：" .. tostring(why))
else
    pending = PrimArtView.begin(parentControl, "Cover", art, 0, 0, 400)
end

-- OnUpdate：每帧最多建 96 个，建完为止
if pending and pending.step(96) then pending = nil end
```

要点：

- **等比缩放。** 位置和尺寸都乘同一个系数 `k = 显示宽度 / w`。宽高用不同系数会让旋转过的图元变形。
- **逐类型模式。** kind 4 的 106057 使用 `Basic`，其余使用表中的 `Stretch`；外层 100001 遮罩仍用 `Stretch`。不要用图片羽化字段代替已标定的纹理衰减。
- **遮罩。** 外层是一张 100001 矩形图片，RGB 为 `bg`；format 3 的 `imageColor` Alpha 取 `art.bgAlpha`，format 1/2 固定取 255。开 `enableMask = true`、`reverseMaskArea = false`，图元全部是它的子控件，超出画面的部分由它裁掉。透明拟合的外层 Alpha 为 0，不画底色；它仍可裁切子图片，依据见 原对话模板项目的《UI 布局与图片语义》 5、7.1 节（`observed`）。子图元全部保持 `enableMask = false`，不增加逐图元遮罩；柔边仍取素材纹理 Alpha。
- **子控件定位。** 图元的锚点放在遮罩左下角 `(0, 0)`，轴心在中心，`anchoredPosition` 直接用表里的中心坐标乘 `k`。
- **分帧。** 每帧最多建约 96 个控件（AGENTS 第六章）。500 个图元约 6 帧建完。页面上同时还有别的创建任务时，共用一个预算。
- **所有权。** `builder.mask` 和 `builder.parts` 交给调用方登记到页面或会话，离开页面时调用 `builder.destroy()`。还没建完就离开时，同样先 `destroy()`，并丢掉 `pending`。
- **整体变换。** 移动、缩放、显隐都作用在遮罩上，不逐个改图元。遮罩放在旋转的父级下如何表现未知（`docs/UI布局与图片语义.md`），不要旋转遮罩或它的父级。
- 嵌入有分端舞台缩放的项目时，`x`、`y`、`width` 按项目自己的适配层换算成父级局部坐标再传入。

## 6. 工具侧说明

以下保留硬图元实现与历史基准；不将历史硬图元对拍或基准直接当作软图元或透明拟合的验证结果。新实现的桌面检查属于 `inferred`，本次结果见 [渐变标定与验证记录](渐变图元标定.md)，新图元引擎实机验证为 `pending`。

- 入口：Diapig Editor 桌面端「更多 → 图元拟合」。浏览器预览模式下不可用。
- 算法：贪心叠加，每个图元先随机取样再爬山微调，颜色用闭式解。Rust 实现在 `src-tauri/primfit/`，由 In Falsus 制谱器的 `primfit.js` 移植而来，之后加了两项改进（2026-11-14）：
  - **按误差取样**：候选图元的中心按当前像素误差加权抽取，不再全图均匀撒点。同样的搜索时间里，相似度高约 0.3 个百分点。
  - **精修**（可关，默认 2 轮）：全部图元加完后，不透明模式先重算背景色（透明模式固定透明底），再自下而上逐个调整已有图元的位置、尺寸、旋转、不透明度和颜色，并可在勾选的类型之间换类型；每轮最后把贡献最小的少数图元搬到别处（2026-11-15 增加，见 [标定记录](渐变图元标定.md) 第 9 节）。目标仍是整图误差。保持形状不变只重算颜色，就是对全部颜色做联合最小二乘的一步。误差只降不升；第 1 轮约提高 0.5 个百分点，第 2 轮约 0.1，之后很小。
  - 两项都不改变数据格式，绘制代码不用动。
- 对拍：`cargo test -p primfit` 用 In Falsus 那份 JS 生成的数据核对随机数、目标图缩小、约 2200 个图元的扫描线、误差变化量和最优颜色；另有精修的测试（误差不升、增量画面与重画一致、中途停止后状态一致）。
- 基准（2026-11-14，1254×1254 测试图，工作分辨率 200，标准强度，8 线程，只测了这一张图）：

  | --- | --- | --- | --- | --- |
  | 300 | 1.8 秒，91.93% | 0.5 秒，91.98% | 0.6 秒，92.25% | 1.1 秒，92.89% |
  | 500 | 3.1 秒，93.26% | 0.8 秒，93.32% | 1.0 秒，93.63% | 1.7 秒，94.23% |

  - 复现基准：`PRIMFIT_IMAGE=<图片> PRIMFIT_GUIDED=1 PRIMFIT_REFINE=2 cargo test -p primfit --release --test bench -- --ignored --nocapture`（两个变量不设就是原算法）。

### 渐变图元（2026-11-15）

默认新增柔边椭圆（kind 4）；单向渐变和对称光带（kind 5/6）可选，界面标为实验类型。每种软图元保留独立同档搜索预算，再与硬图元候选比较；硬图元关闭软类型后仍走原路径。软图元评分按覆盖像素计算，通常比硬图元的按行前缀和更慢。

加入、重画、前缀相似度与精修共用同一透明度模型；精修可以在勾选的类型之间换类型，并把贡献最小的图元搬到别处。软边候选在搜索时用多级降采样近似评估，选定后按逐像素公式复算；各种软图元共用一份搜索预算（2026-11-15，见 [标定记录](渐变图元标定.md) 第 8 节）。上层透过率使用逐像素对数累计与完全不透明计数，避免大量重叠后下溢再相除。候选和爬山循环支持取消，已有图元保留。详细曲线、误差、样例和实机验收步骤见 [标定记录](渐变图元标定.md)。

### 保留透明背景（2026-11-15）

「保留透明度」复选框默认关闭。关闭时，RGBA 源图先按「透明处底色」（matte）合成为不透明 RGB，再面积平均缩小，沿用 format 1/2 的原有路径。开启时隐藏且忽略旧 matte 设置，原图和拟合结果以棋盘格辅助查看透明区域；棋盘格不进入数据或导出。切换仅更新原图预览，已有结果需重新拟合才应用新设置。「高级参数」使用可折叠面板收纳搜索、精修等设置。

透明模式直接处理 RGBA：源像素先以 `A/255` 预乘 RGB，再对三个预乘色通道和 A 分别做面积平均，得到工作分辨率目标；不先用底色合成，也不直接平均未预乘 RGB，以免透明像素里隐藏的颜色污染边缘。拟合从全零透明画布开始，`bg=0,bgAlpha=0`；精修不重算不透明背景。图元仍按从下到上的 source-over 叠加，颜色记录保持非预乘 RGBA。

损失函数同时比较目标与拟合结果的三个预乘 RGB 通道和 Alpha，四个通道等权。设像素数为 N，各通道取值均为 0–255，透明模式归一化 RMSE 为 `sqrt(Σ(ΔpremulR² + ΔpremulG² + ΔpremulB² + ΔA²) / (4N)) / 255`；原不透明 RGB 模式的分母仍为 `3N`。相似度按各自归一化误差计算，因此两种模式的相似度数值不能直接横向比较；前缀、重画与精修都应沿用该模式的同一误差模型。

这是对颜色和透明度的图元近似，不是逐像素复制原图 Alpha。形状重叠会累计不透明度，边缘或透明区可能出现 Alpha 外溢；偏离目标的 Alpha 进入同一损失惩罚，但有限图元无法保证完全消除。矩形边界外由唯一的父遮罩裁切，画面内部不增加逐图元遮罩来强行复制轮廓。

全透明源图不需要任何图元：允许保留并导出 `format=3,bg=0,bgAlpha=0,shapes={}`。透明结果选择前 0 个图元也得到同样的有效空透明画布；选择硬图元前缀仍保留 format 3。格式约定允许读取 `bgAlpha=0–255`，当前透明拟合生成的值固定为 0。


### 保留透明度与高级参数（2026-11-15）

- 「图片与参数」保留图元数量、工作分辨率、保留透明度、条件显示的透明处底色与图元类型。搜索强度、不透明度、精修、随机种子、线程数放在默认收起的「高级参数」卡片；展开/收起不重置这些值。

### 重点区域（加权误差）（2026-11-15）

- 入口：「高级参数 → 重点区域 → 编辑…」打开对话框，在原图预览上用笔刷涂抹 / 擦除（半径、不透明度即权重、羽化宽度可调；快捷键 B / E、`[` `]`、Ctrl+Z / Ctrl+Shift+Z），或按「细节」（亮度梯度模糊后归一化）/「中心」（椭圆高斯）自动生成；按「确定」才写回。「原图」预览上叠一层淡主题色显示当前蒙版。蒙版只在本次运行期间保留，换图片（路径或预览尺寸变化）时清除；只改底色或保留透明度时保留。不随参数写入本地设置。
- 做法：蒙版与原图预览同尺寸（长边 ≤ 512，0–255）。开始拟合时后端按面积平均缩放到工作分辨率，换算为逐像素权重 `ω = 1 + gain × m / 255`，`gain` 固定为 8（满强度处误差权重 9 倍）；蒙版全为 0 时不加权。拟合器优化的误差从 `Σ(F − T)²` 改为 `Σ ω·(F − T)²`：所有逐像素累加量（前缀和、软边多级格子、精修窗口、背景色最小二乘、逐像素增量）都对 ω 线性，闭式最优颜色和误差变化量的公式形式不变；按误差取样随之变为按加权误差取样。初始背景色仍取不加权平均色，精修重算背景色时按 ω 加权。
- 相似度仍是不加权的整图误差（界面、前 k 个图元的相似度、导出注释都一样），不同设置之间可比；设了重点区域后整图相似度通常略降。
- 不改数据格式（format 1–3）、绘制代码与 Agent 提示词。
- 证据 `inferred`（桌面测试），不涉及引擎，实机状态 `not_required`：
  - 权重全为 1 与不传权重时，贪心 + 精修的图元、背景色和误差逐位相同（硬边、软边、透明三组）；原有测试与 JS 对拍不变。
  - 随机权重下，评估给出的误差变化量与逐像素暴力计算的加权误差之差一致；精修后的误差与从头计算一致且不升；最优颜色任一通道改 ±1 不会更好。
  - 基准（`cargo test -p primfit --release --test weights_bench -- --ignored --nocapture`，工作分辨率 200，柔边椭圆 + 三种硬图元，标准强度，精修 2 轮，8 线程，3 个种子取平均）。重点区域 = 缩放后蒙版过半的像素：
