# 对话草稿格式

草稿是给人和 AI 手写的精简 JSON，由命令行转成编辑器能打开的游戏对话结构体 JSON。转换与校验逻辑在 `src/model/draft.ts`，与编辑器共用 `src/model/codec.ts`。

## 命令

在仓库根目录运行：

```bash
npm run draft -- check 草稿.json
npm run draft -- build 草稿.json -o 对话.json --ids-from 已有对话.json
npm run draft -- dump 对话.json -o 草稿.json
```

- `check` 只校验。有错误时退出码为 1。
- `build` 校验通过后写出游戏对话 JSON；有错误时不写文件。不写 `-o` 时输出到草稿旁边的 `<草稿名>.dialog.json`。输出文件已存在时需加 `--force`。
- `dump` 把已有对话转成草稿，用于让 AI 在现有对话上修改。不写 `-o` 时输出到终端。
- `--ids-from` 从已有对话文件带入三个结构体 ID。

生成后用编辑器打开对话 JSON 检查，再按原流程导入游戏。

## 示例

完整示例见 `examples/示例.draft.json`。

```json
{
  "nodes": [
    {
      "title": "向导",
      "subtitle": "奇域管理员",
      "content": ["欢迎来到这里，<PLAYER_NAME>。", "要先听一下<color=#FFCC33>规则</color>吗？"],
      "choices": [
        { "text": "听一下规则" },
        { "text": "直接开始", "goto": "开始" }
      ],
      "default": 1,
      "duration": 5
    },
    { "content": "规则很简单：收集三枚徽记，然后回到这里。" },
    { "id": "开始", "title": "向导", "content": "那就出发吧！", "leave": "开始游戏" }
  ]
}
```

## 顶层字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `nodes` | 是 | 节点数组，顺序即游戏里的节点序号（从 0 起） |
| `start` | 否 | 开始节点（节点引用），默认第 0 个 |
| `ids` | 否 | `{ "dialog", "node", "branch" }` 三个结构体 ID，新结构再加 `beginEnd`（对话起止设置）；优先于 `--ids-from` |
| `blackout` | 否 | 起止黑场（只用于锁定对话）：`{ "enter": 秒, "enterEvent": 事件名, "leave": 秒, "leaveEvent": 事件名 }`，字段都可省略 |

结构体 ID 来自游戏编辑器，不能编造。草稿里不写时用 `--ids-from` 带入，或生成后在编辑器里填写。

**新旧两种对话结构体**：新结构比旧结构多一个「起止设置」字段。写了 `blackout`、或 `ids` 里有 `beginEnd`（包括从 `--ids-from`、被覆盖的原文件带入）时输出新结构，否则输出旧结构。游戏里的对话结构体还没加这个字段时不要写 `blackout`。

`blackout` 的 `enter` / `leave` 是开始前 / 结束后**全黑后停留的秒数**，0 或省略表示不加这段黑场；`enterEvent` / `leaveEvent` 在屏幕全黑时派发，服务器可以趁这时调整镜头、摆放角色等，玩家看不到。

## 节点字段

| 字段 | 说明 |
| --- | --- |
| `id` | 节点名，供其他节点引用；不被引用的节点可以不写 |
| `title` | 标题。**省略表示沿用上一节点的标题和副标题** |
| `subtitle` | 副标题，省略表示没有。只能和 `title` 一起写 |
| `content` | 必填。字符串，或按行给出的字符串数组 |
| `goto` | 跳到指定节点（节点引用） |
| `choices` | 分支选择：`[{ "text": 选项文字, "goto": 节点引用 }]`；`goto` 省略表示跳到下一个节点 |
| `default` | 限时选择超时后选中的分支，写 `choices` 的下标，默认 0 |
| `end` | `true` 表示在这里结束对话 |
| `mode` | 显示模式：`default`（按对话类型：锁定对话为打字机，其余为整段渐显）、`typewriter`（打字机）、`fade`（整段渐显）、`instant`（直接显示） |
| `enter` / `leave` | 进入 / 离开节点时触发的事件名 |
| `duration` | 时长（秒），含义随对话类型而变，见下 |

**节点引用**写目标节点的 `id`，也可以写节点序号；建议一律用 `id`，增删节点后不会错位。

**流程**：`goto`、`choices`、`end` 最多写一个。都不写时顺序进入下一个节点，最后一个节点自动结束。

**时长**（依据仓库 `docs/对话规格.md`）：

| 对话类型 | `duration` 的含义 |
| --- | --- |
| 锁定对话 | 继续按钮出现前的延迟；0 时为 0.5 秒 |
| 非锁定对话 | 自动进入下一节点的等待时间，最少 2 秒；带 `choices` 时是选择的限时 |
| 黑屏文字 | 自动进入下一段的等待时间，最少 2 秒 |

同一份对话数据用于哪种类型由游戏里创建对话时决定，草稿里不记录。

## 内容写法

- 换行直接写真实换行（JSON 里的 `\n`），或用字符串数组每行一个元素；转换时会换成游戏用的字面量 `\n`。
- 玩家名写 `<PLAYER_NAME>`，可用在标题和内容里。
- 富文本只支持 `<color=#HEX>…</color>`（3 / 4 / 6 / 8 位十六进制）、`<b>…</b>`、`<i>…</i>`；其他尖括号内容按字面显示。

## 校验

出现错误时不生成文件：

- 未知字段（防止拼错字段名）、字段类型不对
- `id` 重复，引用的 `id` 不存在，节点序号越界
- `goto`、`choices`、`end` 同时出现
- `choices` 为空，`default` 超出分支范围，最后一个节点的分支没写 `goto`

只提示、仍会生成：

- 分支超过 4 个，或默认分支不在前 4 个之内（非锁定对话只显示前 4 个）
- 富文本标签未闭合或格式不对
- 从开始节点走不到的节点
- 第一个节点没有标题、内容为空、结构体 ID 未填全

校验通过后会列出用到的事件名。事件名是否与服务器侧一致，工具无法判断，需要人工核对。
